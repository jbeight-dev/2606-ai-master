To facilitate a better understanding of the various metrics within the Scan Operator, the following diagram demonstrates the associations between these metrics and storage structures.
To retrieve data from disk and apply the predicates, the storage engine utilize several techniques:
Data Storage
: Encoded and compressed data is stored on disk in segments, accompanied by various indices.
Index Filtering
: The engine leverages indices such as BitmapIndex, BloomfilterIndex, ZonemapIndex, ShortKeyIndex, and NGramIndex to skip unnecessary data.
Pushdown Predicates
: Simple predicates, like
a > 1

Late Materialization
: Only the required columns and filtered rows are retrieved from disk.
Non-Pushdown Predicates
: Predicates that cannot be pushed down are evaluated.
Projection Expression
: Expressions, such as
SELECT a + 1
, are computed.

Join Operator is responsible for implementing explicit join or implicit joins.
During execution the join operator is split into Build (hash-table construction) and Probe phases that run in parallel inside the pipeline engine. Vector chunks (up to 4096 rows) are batch-hashed with SIMD; consumed keys generate runtime filtersâBloom or IN filtersâpushed back to upstream scans to cut probe input early.
Join Strategies
StarRocks relies on a vectorized, pipeline-friendly hash-join core that can be wired into four physical strategies the cost-based optimizer weighs at plan time:

What makes it fast
